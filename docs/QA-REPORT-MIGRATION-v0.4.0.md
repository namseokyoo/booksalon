## 3. 서비스별 코드 분석 결과

### 3.1 UserService (사용자 서비스)

| 검증 항목 | 결과 | 상세 |
|----------|------|------|
| **CRUD 메서드 구현** | ✅ Pass | 프로필 생성/조회/수정/삭제 완비 |
| **기존 인터페이스 호환** | ✅ Pass | Firebase UserProfile과 호환되는 인터페이스 유지 |
| **관련 데이터 조회** | ✅ Pass | 소셜링크, 알림설정, 선호장르 JOIN 처리 |
| **에러 처리** | ✅ Pass | 적절한 에러 메시지 반환 |

**Gemini 검토 결과:**
- 동시성 이슈: `incrementStat`에서 Race Condition 가능 (Minor - 트리거 권장)
- 타입 안전성: `as never` 캐스팅 사용 (타입 추론 약화)
- 누락 필드: `following`, `followers`, `bookmarkedForums` 조회 로직 없음 (인터페이스에만 존재)

**권장 개선사항:**
1. `incrementStat`을 PostgreSQL RPC로 대체 (Atomic 연산)
2. `as never` 제거 및 정확한 타입 정의 적용
3. 사용자 생성 시 관련 테이블 자동 생성 DB Trigger 도입 고려

### 3.2 RatingService (평점 서비스)

| 검증 항목 | 결과 | 상세 |
|----------|------|------|
| **평점 CRUD** | ✅ Pass | 저장/조회/삭제 완비 |
| **평점 분포 조회** | ✅ Pass | 1-5점 분포 계산 |
| **평균 평점 업데이트** | ✅ Pass | forums 테이블 동기화 |
| **유효성 검사** | ✅ Pass | 1-5 정수 검사 |

**Gemini 검토 결과:**
- 동시성 이슈: `setUserRating`에서 "조회-계산-쓰기" 패턴 (Race Condition 위험)
- 성능 이슈: 평균 계산 시 모든 데이터를 클라이언트로 로드 (확장성 문제)
- 트랜잭션 부재: ratings 저장 후 forums 업데이트 실패 시 불일치

**권장 개선사항:**
1. Supabase `upsert` 활용 (onConflict로 원자적 처리)
2. PostgreSQL Trigger로 평균 자동 업데이트
3. 대량 데이터 시 DB 집계 함수(AVG, COUNT) 활용

### 3.6 SocialService (소셜 서비스)

| 검증 항목 | 결과 | 상세 |
|----------|------|------|
| **팔로우/언팔로우** | ✅ Pass | 토글 방식 구현 |
| **좋아요 토글** | ✅ Pass | 게시물/댓글 분리 |
| **팔로워/팔로잉 목록** | ✅ Pass | 사용자 정보 포함 |
| **활동 피드** | ✅ Pass | 본인/팔로잉 피드 |

**Gemini 검토 결과 (Critical):**
- **동시성 이슈**: 좋아요 카운트 업데이트에서 심각한 Race Condition
  - "조회-계산-쓰기" 패턴으로 동시 요청 시 카운트 유실 가능
- 트랜잭션 부재: likes 테이블 INSERT와 카운트 UPDATE 분리
- 페이지네이션 부재: 팔로워/팔로잉 목록에 limit 없음

**권장 개선사항 (필수):**
1. PostgreSQL Trigger로 like_count 자동 업데이트
2. `toggleFollow`에서 UNIQUE 에러(23505) 처리
3. 팔로워/팔로잉에 페이지네이션 추가
